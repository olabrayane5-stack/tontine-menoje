# AGENTS.md

## What this is
React 19 + Vite 8 + TypeScript SPA/PWA for a French church tontine (savings) manager. No router or backend: all state lives in `src/App.tsx`, seeded from `src/data/mockData.ts`, and persisted to `localStorage` through `src/hooks/usePersistentState.ts` under the `tontine-menoje:v1:` prefix.

## Commands
- `npm install`
- `npm run dev` — Vite on port 3000, bound to `0.0.0.0`
- `npm run lint` — the only verification: `tsc --noEmit` with `strict`. No ESLint, Prettier, or test suite. Run it before finishing.
- `npm run build` — production build into `dist/`
- `npm run preview` — serve the production build (needed to test the service worker)
- `npm run clean` — cross-platform removal of `dist/`

## Architecture
- `src/App.tsx` owns all state (`users`, `versements`, `retraits`, `sundaysList`, `annonces`, `parametres`) and passes callbacks down. New IDs use `Math.max(...ids) + 1`.
- Session is the persisted `currentUserId`; `currentUser` is derived from `users`. `currentUser.role` selects `AdminDashboard` vs `MemberDashboard`; the active tab is local state. `LoginScreen` matches phone + **plaintext** password from `mockData.ts` (demo logins `admin`, `123`, `temp`) and offers quick-login buttons. Not real authentication.
- Domain model: `src/types/index.ts`. Business rules: `src/utils/tontineUtils.ts` — `calculateUserStats` computes the church retention (`tauxRetenue`, from `parametres.pourcentage_retenue`), consecutive-Sunday streak, points, and badges; message and assistant generators live here too. Pass the rate explicitly: `calculateUserStats(id, versements, retraits, sundaysList, parametres.pourcentage_retenue)`.
- Collecte du dimanche (admin, section « Saisie ») : registre **déclaratif**, l'app n'encaisse rien. Mode par défaut « Par membre » (`src/components/AdminDashboard.tsx`) : liste alphabétique des membres actifs plus les inactifs déjà notés (avatar avec initiales, montant du dimanche ou dernier montant connu), recherche insensible aux accents (`normalizeText`), filtres Tous / À noter / Notés, barre de progression. Toucher une ligne ouvre le **pavé de collecte** (dialogue plein écran, `#collecte-amount` en `inputMode="numeric"` autofocus, raccourcis 1 000 / 2 000 / 5 000 / 10 000 et « Comme la dernière fois », cumul du membre). « Enregistrer » ferme, « Enregistrer et suivant » (ou Entrée) enregistre puis ouvre le prochain membre non noté (`findNextPendingMemberId`, avec bouclage) : la saisie s'enchaîne sans revenir à la liste. Second onglet « Texte rapide » (ex-« IA ») : texte libre analysé par `parseVersementsBatchText` puis validé.
- Invariant : **un seul versement par `user_id` + `date_dimanche`**. Toute écriture de versement passe par `upsertVersements` (`src/utils/tontineUtils.ts`), appelé depuis `handleAddVersement` / `handleAddBatchVersements` dans `App.tsx` : l'entrée existante est mise à jour, sinon créée, avec des IDs calculés dans le `setState` fonctionnel (pas de collision en enregistrement groupé). Ne jamais réintroduire de `setVersements(prev => [...prev, ...])` direct. `parseAmountInput` tolère « 10 000 » / « 10.000 » et ignore les saisies vides.
- Backup/export: `src/utils/backup.ts` builds a versioned JSON backup (`app: 'tontine-menoje'`, `version: 1`) with validation and a `;`-separated CSV (UTF-8 BOM for Excel). `src/components/BackupCard.tsx` handles download/restore and `src/components/SundayManager.tsx` adds/removes Sundays (a Sunday with versements cannot be deleted). Both are rendered in the admin Réglages section; restore handlers live in `App.tsx` (`handleRestoreData`, `handleAddSunday`, `handleDeleteSunday`).
- Animations: `src/components/motion/PageTransition.tsx` (Framer Motion, ~0.4 s) wraps the admin/member sections and `src/components/motion/Stagger.tsx` (`Stagger` / `StaggerItem`) cascades cards; `src/components/AnimatedAmount.tsx` counts money values from 0 to the target (~1.2 s, `requestAnimationFrame`, formats with `formatMoney`). `src/components/ui/Modal.tsx` (backdrop, Échap, scroll lock, `role="dialog"`) and `src/components/ui/Toast.tsx` (`ToastProvider` + `useToast`, `role="status"`) are the shared overlay primitives; `src/components/ui/Skeleton.tsx` is the loading placeholder (no spinners). Legacy CSS helpers `.page-transition`, `.animate-rise` / `.animate-pop` and `.btn-sheen` still exist in `src/index.css`. All motion is limited to `transform` / `opacity` and is disabled under `prefers-reduced-motion` (`useReducedMotion` + the CSS media query). The theme toggle uses the View Transitions API with a reduced-motion fallback.
- The "IA" features are deterministic keyword matching in `tontineUtils.ts`, not Gemini calls. The unused Gemini/Express/dotenv/motion/tsx dependencies were removed; only `react`, `react-dom`, `lucide-react`, Vite and Tailwind remain (plus `@types/node`, needed by `vite.config.ts`). Nothing under `src/` reads env vars or calls an API.
- PWA is implemented: `public/manifest.webmanifest`, `public/sw.js`, and generated icons in `public/icons/`. The service worker is registered **only in production** (`import.meta.env.PROD`), so test it with `npm run build && npm run preview`, not `npm run dev`. The install button uses `beforeinstallprompt` with an instructions fallback.
- Design system: the single source of truth is `src/styles/theme.css` (CSS variables: brand navy `#14213d`, gold `#e0a526`, positive `#1f9d6b`, error `#d64545`, page `#f6f7fb`, surfaces, borders, text, radii incl. 16 px cards, shadows, fonts, durations, plus the `.dark` block). It is imported at the top of `src/index.css`, which also remaps the Tailwind palette in `@theme` (slate → navy, amber → gold, emerald → positive, rose/red → error, blue/sky → info) so existing utility classes follow the theme, and defines the reusable classes `.app-card`, `.app-card-interactive`, `.app-header`, `.app-hero`, `.app-hero-ring`, `.app-chip`, `.app-stat-tile`, `.btn` (`-primary` / `-accent` / `-outline` / `-ghost` / `-danger`, sizes `-sm` / `-lg`, 44 px min target), `.field` / `.field-label` / `.field-error`, `.badge-*`, `.skeleton`, `.progress-track` / `.progress-fill`, `.mobile-nav*` and `.hide-scrollbar`. They live in `@layer components`, so Tailwind utilities (e.g. `hidden`, `rounded-[2rem]`) override them; prefer these over ad-hoc card/gradient styles so light and dark mode stay consistent. Fonts are local: Poppins (headings, `font-display`) + Inter Variable (body), imported from `@fontsource*` so the PWA works offline. Components should not hardcode colors — use the tokens/utilities.
- Layout: mobile-first. Fixed bottom navigation (`.mobile-nav`) under `sm`, header + desktop nav above; tables become stacked cards on mobile (`sm:hidden` cards + `hidden sm:block` tables); touch targets ≥ 44 px; amounts formatted `25 000 FCFA` via `formatMoney`.
- Theme: `src/hooks/useTheme.ts` keeps a module-level store (`useSyncExternalStore`) and toggles the `dark` class on `<html>`; `src/components/ThemeToggle.tsx` is mounted in the app header and on the login screen. Dark styling is implemented as explicit class overrides in `src/index.css` (the components do not use `dark:` utilities), so any new color utility may need a matching dark override. Theme choice is stored under `tontine-menoje:theme` (separate from the demo-data reset) and applied pre-paint by an inline script in `index.html`. Toggling uses the View Transitions API with a reduced-motion fallback.
- `src/components/TechGuideModal.tsx` contains the intended production MySQL schema and PHP/PDO API layout (InfinityFree deployment) as JSX template strings. Treat it as the backend spec; it does not execute.

## Conventions and gotchas
- The `@` alias resolves to **`src/`** (`vite.config.ts` + `tsconfig.json`). Existing code still uses relative imports.
- Tailwind v4 through `@tailwindcss/vite`; one `@import "tailwindcss"` in `src/index.css`. There is no `tailwind.config.js`.
- `DISABLE_HMR=true` disables HMR and file watching (AI Studio behavior). Do not remove it.
- Persisted data uses the versioned `tontine-menoje:v1:` prefix. Bump that version if you change stored shapes, otherwise old `localStorage` payloads will break the app. Admins can reset via the footer's « Réinitialiser la démo » button.
- Seed data has 50 users and 10 Sundays ending `2026-03-08` in `mockData.ts`; several components default to that date. The calendar is now editable from the admin Réglages section, but changing the seed still means updating `SUNDAYS_LIST` and those defaults.
- `parametres.pourcentage_retenue` (default 3) is the single source of truth for the church retention. Never hardcode `3%` / `0.03` in new UI or calculations.
- Any new `localStorage` key must stay under `tontine-menoje:v1:` and be added to `AppData` if it belongs in a backup.
- Keep UI text, identifiers, and domain vocabulary in French.
